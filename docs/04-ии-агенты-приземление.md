# 04 · ИИ-агенты — приземление спецификации

> Спецификация автономных агентов (фаза Design, документ 2) — принята к работе,
> но пропущена через фильтр «не вширь, а вглубь» и реальность одиночной Unity-игры.
> Формат: **Берём сейчас / Адаптируем / Откладываем**. Это дисциплина FPF: не схлопываемся
> на красивой спеке, а называем, что она стоит в *нашем* проекте.

---

## Берём сейчас — в ядро и в срез «Первая ночь»

Это фундамент, без него эмерджентность не работает. Стоит дёшево, окупается сразу.

- **Equality of Rules.** Агент не имеет God Mode: не лезет в память движка и скрытые переменные, действует только через сенсоры и Use Cases, ограничен теми же инвариантами (ресурсы, пространство, время), что и игрок. Это ровно наш принцип «игрок = ИИ через одни Use Cases».
- **Цикл ORA (Observe→Reason→Action)** для NPC. Action всегда = вызов Use Case. Для среза Reason = дерево поведений (дёшево), без LLM.
- **Event-Driven Choreography.** Нет центрального Game Master. Агенты публикуют события и реагируют на чужие через свои Use Cases. Берём типы триггеров как готовый словарь событий: `WorldStateChanged`, `EntityProximity`, `InternalNeedAlert`, `DirectContractRequest`, `SystemInvariantViolation`.
- **Rich Domain, запрет анемичных моделей.** Логика внутри сущностей (`takeDamage` инкапсулирует смерть, `addItem` проверяет вес). Совпадает с арх-отчётом 03.
- **Quality Gates (3 фазы).** Research→Design→Plan/Implement с ревью агентом-критиком и запретом идти дальше без прохождения тестов. Это и есть наш пайплайн; сохраняем `research_result.md` как артефакт фазы 1.
- **Untrusted Input / Input Firewall.** Имена предметов и реплики игрока — недоверенный ввод. Защита от prompt injection обязательна, как только появится хоть один LLM-NPC. Стоит копейки, ставим сразу в дизайн.

---

## Адаптируем — идея верная, реализация под нас проще

- **Формула качества Observe** `Quality = (Correctness·Completeness)/(Size·Noise)`. Для BT-мобов это просто правило «агент видит только окрестность, не весь мир» (радиус наблюдения + семантический фильтр). Полная формула включается только для LLM-агентов.
- **Правило 40–50% контекста + суммаризация + суб-агенты.** Дисциплина контекста — да, но применяется **только к LLM-NPC** (которых на старте ноль). Для дерева поведений понятия «контекстное окно» нет. Держим как правило для слоя 3 автономии.
- **Long-term / RAG (pgvector/Redis).** Правильно по сути (мир помнит), но нужен **только глобальным сюжетным агентам** («Правитель фракции»). До их появления long-term память — это просто факты в `GameState`/сейве. Векторную БД добавляем, когда реально появится LLM-агент с долгой памятью, не раньше.
- **MCP как инструменты агента.** Концептуально Tools = Use Cases. В рантайме одиночной игры городить MCP-протокол между NPC и миром не нужно — это прямые вызовы Use Cases в одном процессе. MCP уместен в **dev-контуре** (агенты-разработчики через эту среду), а не внутри игры.

## Откладываем / не тащим — импорт из трейдинг-движка, не из геймдева

Честно: это пришло из твоего `lemon-ref`/PolyTerminal (биржа), а не из нужд уютного Вальхейма. Для одиночной игры — оверинжиниринг. Не выкидываем совсем, но не на старте.

- **Rust для OMS / Execution Worker.** Наше ядро — **чистый C#**, оно и так тестируется без Unity и тикает вне FPS. Второй язык (Rust) = вторая сборка, FFI-мост, вдвое больше боли. Rust оправдан только если пойдём в **серверный многопользовательский** мир с сотнями агентов на бэке. Для single-player — нет.
- **HFT-ready / Optimistic Ledger / Rollback.** Оптимистичное исполнение с откатом нужно, когда есть **сетевой авторитет и рассинхрон клиент-сервер**. В одиночной игре состояние локально и авторитетно — откатывать не у кого. Механизм `Validate`+`Apply` (твой `Commands`) уже даёт атомарность: не прошло Validate — Apply не случился.
- **Nonce-management / EIP-712 / ActionQueue как в блокчейне.** Очередь действий агенту нужна, но не в криптоформате. Обычная детерминированная очередь тиков достаточна. Nonce — из ончейн-мира, здесь лишний.
- **Batch API / Context Caching для снижения стоимости 50–70%.** Реальная экономия — но включается вместе с первым LLM-агентом. Пока LLM в игре нет, экономить нечего.

## Software 3.0 — как относимся

Тезис «естественный язык = исходный код, LLM = компилятор контекста» — вдохновляющий и для **dev-контура** (мы правда так и строим игру: намерение текстом → агенты → код). Внутри игры на старте LLM не нужен: эмерджентность рождается из BT-агентов + event choreography, а не из LLM. LLM-NPC — это слой 3 автономии, дорогой и точечный (важные сюжетные персонажи), включается, когда ядро уже приносит удовольствие.

## Итог: карта автономии по слоям (сводит арх-отчёт и эту спеку)

| Слой | Reason | Память | Стоимость | Когда |
| --- | --- | --- | --- | --- |
| 0 — реактив | распорядок/триггеры | нет | ~0 | срез «Первая ночь» |
| 1 — короткие цели | дерево поведений | short-term (C#) | низкая | сразу после среза |
| 2 — долгие цели | utility-AI | short-term + факты в сейве | низкая | когда мир должен жить без игрока |
| 3 — сюжетные LLM-агенты | LLM + CoT | long-term RAG (pgvector) | высокая, дозируем | когда есть кор-удовольствие и нужен «Правитель» |

**Правило:** каждый следующий слой включаем, только когда предыдущий доведён до кайфа и стабилен. HFT/Rust/ledger — не раньше решения делать серверный мультиплеер (отдельная большая развилка, не сейчас).
