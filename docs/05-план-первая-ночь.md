# 05 · Implementation Plan — вертикальный срез «Первая ночь»

> Фаза PLAN пайплайна. Берёт стандарт из арх-отчёта (03) и спеки агентов (04)
> и превращает в **пошаговый порядок работ именно для первого среза**.
> Принцип: ядро сначала, Unity потом; каждый шаг проверяем; не идём дальше без гейта.

---

## Цель среза

Один час игры до «вау»: игрок появляется в красивом биоме → добывает дерево/камень → ставит укрытие из модульных деталей → наступает ночь со светом/погодой/эмбиенсом → приходит один живой NPC с именем, лицом и распорядком, с ним можно поговорить. Если NPC погибнет — именная могила.

Что срез доказывает: красота мира, добыча, стройка, время/атмосфера и **душа** (живой NPC) работают на чистом ядре, а игрок и NPC ходят через одни Use Cases.

---

## Структура решения (сборки asmdef)

Три сборки, зависимости строго внутрь. Гейт проверяется механически.

```
Game.Domain      →  без ссылки на UnityEngine   (Rich Entities, события)
Game.Application →  ссылается на Domain          (Use Cases, интерфейсы портов, Event Bus)
Game.Unity       →  ссылается на оба + UnityEngine (адаптеры, презентеры, View)
Game.Tests       →  ссылается на Domain+Application (headless, без графики)
```

**Dependency Audit (Gate A):** в `Game.Domain` и `Game.Application` — ноль `using UnityEngine / UnityEditor / TMPro`. Координаты — `System.Numerics.Vector3` или свой `struct`, не `UnityEngine.Vector3`.

---

## Порядок работ (жёсткий)

### Фаза 0 — Каркас проекта
1. Новый Unity 6000.5.3f1 (URP). Три asmdef по схеме выше.
2. Перенос из архива в `Game.Domain`/`Application` (очистка от Unity): `GameState`, реестры (`Item/Recipe/Crop`), `WorldClock`, `WeatherSystem`.
3. Перенос `SyntyMaterialFixer` (Editor) + `AssetLibrary`+`AssetMap` в `Game.Unity`. Скопировать паки Synty.
- **Gate 0:** проект собирается в batchmode; фиксер прогнан — модели не серые (проверка на 1 тест-сцене).

### Фаза 1 — Доменное ядро (чистый C#, без Unity)
4. Rich Entities: `Inventory` (вес/вместимость, `AddItem`/`RemoveItem` с инвариантами), `Character` (`ApplyDamage`, смерть, ХП≥0, приватные поля), `WorldState` (обёртка над `GameState`+время+погода), `Structure`/`BuildingPiece` (стыковка, «не в воздухе», стоимость).
5. Event Bus + реестр событий: `TreeChoppedEvent`, `StructurePlacedEvent`, `CharacterDamagedEvent`, `EntityKilledEvent`, `DialogueStartedEvent`, `NightFellEvent`.
- **Gate 1 (Logic Integrity):** ХП/ресурсы нельзя изменить в обход методов сущности; объект всегда валиден или не создаётся.

### Фаза 2 — Use Cases (интеракторы)
6. `ChopTreeUseCase`, `GatherStoneUseCase`, `PlaceBuildingPieceUseCase`, `TalkToUseCase`. Каждый: DTO вход → загрузка Entity через порт → бизнес-логика в Entity → публикация события → Response.
7. Порты (интерфейсы) для мира/спавна/времени — реализации живут в Unity-слое.
- **Gate 2 (Headless Testing):** на каждый Use Case — юнит-тест в `Game.Tests`, проходит без графики. Пример: «`ChopTree` при полном инвентаре → отказ по вместимости, событие не опубликовано».

### Фаза 3 — ORA для одного NPC (дёшево, без LLM)
8. `NpcBrain`/`NpcTicker` (перенос) → цикл Observe (окрестность, радиус) → Reason (дерево поведений: спать ночью, идти к костру, реагировать на игрока) → Action (вызов Use Cases). `Genome`/`Phenotype` дают уникальное лицо, `Dialogue` — реплики, `GraveViews` — могила.
- **Gate 3 (AI Consistency):** `TalkToUseCase`/действия одинаковы при вызове игроком и NPC. NPC не меняет поля Entity напрямую.

### Фаза 4 — Unity как визуализатор
9. Движение + камера **заново** (лицо игры). `InputRouter` → DTO.
10. Презентеры: подписка на события, спавн префабов через `AssetLibrary`, анимации (Humanoid-ретаргет), правило «HP<0 → Destroy» — в презентере, не в домене.
11. Атмосфера: `DayNightController`, `AmbienceController`+`ProceduralAudio`, `AmbiencePostFx`. `AdminPanel` (F1) включить сразу — окупается.
- **Gate 4:** физика используется только как сенсор (никаких расчётов урона/экономики в `OnCollisionEnter`/`Update`).

### Фаза 5 — Мир и свет (метод Synty)
12. Вживить авторскую сцену выбранного биома (`AuthoredWorldSetup`), НЕ процедурка.
13. Свет золотого часа: солнце (1,0.77,0.48) I=1.2, тёплый туман (1,0.83,0.62) 5→500, прохладный ambient, Bloom+Vignette (HDR вкл!), плотные осмысленные кластеры.
- **Gate 5:** скриншот-ревью — кадр читается как открытка; fps в норме на целевом железе.

## Разбивка в Jira (эпик среза)

- **Эпик:** «Вертикальный срез: Первая ночь».
- **Истории** = фазы 0–5 выше. **Задачи** внутри = пронумерованные шаги, каждая несёт свою фазу пайплайна и критерий гейта.
- Метки агентов-исполнителей: `architect` (Design-ревью), `coder` (Implement), `qa` (гейты сборки/тестов), `art` (сцена/свет).
- Правило: задача не закрывается без прохождения своего Gate; Implement не мёржит в main без QA-агента и твоего ревью.

---

## Итоговые Quality Gates (принять срез)

1. **Dependency Audit** — ноль Unity-ссылок в Domain/Application.
2. **Logic Integrity** — инварианты не обходятся.
3. **Headless Testing** — механики и ORA покрыты юнит-тестами без графики.
4. **AI Consistency** — один Use Case, идентичное поведение для игрока и NPC.
5. **Feel** — «Первая ночь» реально приносит удовольствие (субъективный, но главный: не вширь, а вглубь).
