# 09 · Оркестрация флота агентов — кто что делает

> Как устроена команда: Юра — CEO/Principal, Claude (Cowork, здесь) — COO/оркестратор,
> исполнители — Cursor / Claude Code / Kimi, движок — Unity. Честно про то, что каждый
> реально может и как они связаны. Правило прежнее: **не вширь, а вглубь** — сначала
> замыкаем один цикл, потом добавляем следующего агента.

---

## 1. Структура управления

- **Юра — CEO / Principal.** Цели, приоритеты, аппрув переходов фаз (Design→Plan→Implement) и **финальный мёрж** в `main`. Последнее слово всегда за тобой.
- **Claude (Cowork, этот чат) — COO / оркестратор.** Держу стратегию и метод (FPF), веду задачи в **Jira** (пишу/уточняю тикеты, комментирую, ставлю метки), ревьюю планы и PR исполнителей на соответствие архитектуре и гейтам, пишу брифы новым агентам, гоняю ресёрч/дизайн через свои субагенты. С тобой общаемся здесь.
- **Исполнители (Cursor / Claude Code / Kimi)** — руки: превращают тикеты в код и PR.
- **Unity** — движок и деталь внешнего слоя, подключается к исполнителям (см. §4).

   пишу/веду    │               │ берут тикеты  │
   (я, COO) ────┘        ┌───────┴───────┬───────┴───────┐

                             │            │               │
                             └──────┬─────┴───────┬───────┘
                                    ▼             ▼
                            GitHub (gamegamegame): ветки → PR
                                    │
                            GitHub Actions: гейты (dotnet test)

- **Jira — единый источник истины по работе.** Я пишу туда задачи; исполнители их берут; статусы/PR видны на тикете (GitHub↔Jira ты уже связал).
- **GitHub — код и ворота.** PR прогоняются через гейты; мёрж — по зелёному CI + твой аппрув.
- **Я держу всех в курсе:** читаю тикеты и PR, комментирую прямо в Jira (исполнители это видят), ревьюю здесь с тобой.

## 4. Как сюда подключается Unity (честно)

Я не могу «жить внутри Unity» или стать фоновым демоном — это не мой формат. Но связать Unity с флотом реально так:

- **Правка Unity-C# в репо** — это делают Cursor и Claude Code напрямую (файлы `Game.Unity`).
- **Драйв самого редактора Unity** — через **Unity MCP-сервер**: он открывает Editor как набор инструментов, и агент (например, Claude Code) может создавать объекты, сцены, запускать плей-мод, читать логи. Подключим, когда дойдём до Unity-слоя; я проверю актуально лучший сервер на тот момент.
- **Сборка Unity в CI** — через **GameCI** (нужна лицензия Unity в секретах). Для гейтов Unity-слоя.

До этого момента вся работа идёт в **чистом C#-ядре без Unity** — там агенты автономны и быстры. Unity включаем, когда ядро готово (наш порядок из плана среза).

## 5. Что я реально делаю vs что требует твоих действий

**Делаю сам (уже могу):** веду Jira (тикеты/метки/комменты/автоправила), пишу дизайн-доки и брифы, ревьюю PR по гейтам, запускаю субагентов для ресёрча/дизайна здесь, готовлю артефакты (правила, планы, промпты ролей).

**Требует твоих кликов (разово):** установка Cursor Marketplace-app + GitHub App; установка Claude Code CLI на машину; подтверждение возможностей/подключения Kimi; включение Unity MCP/GameCI на Unity-фазе; финальные мёржи.

Я не переоцениваю: «полная автоматизация» — это цель, к которой идём слоями, а не тумблер. Каждый подключённый агент сначала проходит один тикет от начала до PR, и только потом получает больше автономии.

## 6. Распределение под срез «Первая ночь» (полосы)

Чтобы не столкнулись — разные тикеты, разные файлы:

- **Cursor** → `SCRUM-14` (Inventory) сейчас; дальше остальное чистое ядро Story 1 (Character, Structure, Event Bus).
- **Claude Code** (когда подключишь) → Use Cases (Story 2, `Game.Application`) — отдельные файлы от Domain, плюс тяжёлые рефакторы; позже — драйв Unity через MCP.
- **Kimi** → низкорисковая параллель: черновые данные реестров (предметы/рецепты), заготовки диалогов NPC, ресёрч по Synty-пакам. Ревью-оппонент на PR.
- **Я (COO)** → дизайн-доки на следующие истории, ревью всех PR, ведение Jira, брифы.
- **Ты** → аппрув фаз и мёрж.

## 7. Дисциплина запуска (важно)

**Сначала замыкаем один цикл.** Пусть Cursor доведёт `SCRUM-14` до PR и мёржа — это доказывает, что петля Jira→код→гейт→мёрж работает. Параллельно я готовлю брифы Claude Code и Kimi и держу их полосы. Как первая петля замкнулась — подключаем второго исполнителя, потом третьего. Один рабочий цикл важнее пяти настроенных интеграций.

## 8. Ближайшие шаги

1. Cursor доводит `SCRUM-14` → PR (идёт сейчас). Я ревьюю по гейтам.

3. Как поставишь Cursor Marketplace-app — я включаю автоправило Jira (`agent-eligible` → назначение).
4. Доходим до Unity-слоя — подключаем Unity MCP + GameCI.
